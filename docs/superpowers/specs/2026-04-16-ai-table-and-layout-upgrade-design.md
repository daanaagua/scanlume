# 2026-04-16 AI 表格识别与复杂版面恢复设计

## 背景

当前 Scanlume 的 `Texto formatado` 只支持 `h1 / h2 / p / br` 四种结构块。
这条链对普通截图、简单海报、轻量 PDF 已经可用，但对下面四类内容支撑不够：

1. 图片里的表格，尤其是带跨行父级字段的表格。
2. 一页中包含多个大图、小图或多个 OCR 区块的页面。
3. 图与图注、图与邻近短文本之间的归组关系。
4. 明显双栏页面的阅读顺序恢复。

前面的验证已经证明：当前线上模型在 `json_schema` 模式下，可以稳定返回 `cells + row_groups + records` 形式的表格结构。因此这次不再停留在实验，而是把能力正式接入产品。

## 目标

### 目标 1：让图片 OCR 能识别表格并结构化输出

当用户在 `Texto formatado` 模式上传图片时，模型不仅可以返回普通文本块，还可以返回表格块。表格块至少要支持：

- 表头
- 普通单元格
- 跨行 / 跨列信息
- 行分组信息
- 可直接用于导出与预览的明细记录

### 目标 2：让 PDF OCR 也能复用同一套结构

PDF 的 OCR 区域与整页 OCR 继续走 `runFormattedOcr`，但不再只接受纯文本块。图片表格、复杂区块、图文混排都通过统一的结构块向下游传递。

### 目标 3：改善复杂页面的阅读顺序

在现有多区域切分的基础上，继续补齐：

- 多图片区块排序
- 图与邻近短文本的归组
- 双栏页的栏内排序与跨栏内容处理

### 目标 4：把“表格图片转文字”做成独立入口

新增独立 SEO 路由，但复用同一套 OCR 工作区，不新建第二套产品流程。

### 目标 5：更新文案，突出 AI 扫描优势

首页、主工具页、工作区提示语都要明确体现：

- 复杂版面比传统 OCR 更强
- 能识别图片里的表格
- PDF 混合页可以结合原生文本与 OCR
- 非 PDF 场景也支持“表格图片转文字”

## 非目标

这次不做下面几类承诺：

1. 不做像素级版面复刻。
2. 不保证极端脏图、小字密表、严重透视拍照都稳定成功。
3. 不做 DOCX 直出。
4. 不做多表格页的精细关系抽取。
5. 不做“完全等同 Excel 还原”的表格编辑器。

## 方案总览

### 一、把结构化 OCR 从单一文本块升级为联合结构

新的 `formatted blocks` 不再只是一组 `type/text/order`。
改成“文本块 + 表格块”的联合结构，保持一个 `blocks` 数组向下游传递。

建议结构：

- 文本块：继续保留 `h1 / h2 / p / br`
- 表格块：新增 `type: "table"`，携带表格元信息与单元格数组

这样可以保证：

- 旧的普通图文 OCR 仍能工作
- 新的表格能力可以无缝落地到图片和 PDF
- `txt / md / html` 三种导出仍共享同一套格式化逻辑

### 二、表格块采用“结构化输出，不靠自然语言描述”

模型输出中，表格块至少包含：

- `title`
- `columns`
- `cells`
- `rowGroups`
- `records`
- `notes`

其中：

- `cells` 负责保留原表的布局关系
- `rowGroups` 用于表示跨行父级字段
- `records` 用于提供稳定、易消费的明细输出

这样既能还原 HTML table，也能平铺成 TXT / Markdown / 搜索索引用文本。

### 三、图片表格优先走同一条 `Texto formatado` 链

本次不单独开新接口。
工作区仍使用原来的 `simple` 与 `formatted` 两个模式：

- `simple`：只要纯文本
- `formatted`：允许返回文本块和表格块

这样可以减少前端分叉，降低产品心智成本。

### 四、PDF 混合页继续使用统一结构块

PDF OCR 的 `page` 和 `region` 识别结果都转成统一的页面块。
原生文本块、OCR 文本块、OCR 表格块共同参与排序。

关键规则：

1. 表格块在排序时视为一个完整块，不把其内容拆散到普通段落队列。
2. 同一区域内的图、图注、邻近短文本优先归组，再参与页面排序。
3. 双栏页先按栏排序，再处理跨栏块。

### 五、增加图文归组与双栏排序能力

在当前 `bbox + lane` 的基础上新增轻量启发式：

- 如果块高度较小、靠近图片区域、文本较短，则优先判断为图注或附属文本。
- 图块与最近图注组成一个阅读组。
- 双栏页中，先识别跨栏标题与全宽块，再做左栏、右栏内部排序。

目标不是做通用文档版面引擎，而是降低目前最明显的误排概率。

## 对用户可见的变化

### 工作区

- `Texto formatado` 文案明确支持表格图片与复杂版面。
- 结果预览里新增表格摘要。
- 表格结果在 HTML 预览中显示为真实表格，不只是段落拼接。
- TXT / MD 导出继续可复制，但会给出更可读的表格平铺结果。

### 首页与工具页

- 首页强调 AI 扫描对表格、双栏、混合 PDF 更有优势。
- `imagem-para-texto` 强化“普通 OCR vs AI 结构化 OCR”的区别。
- 新增 `表格图片转文字` 独立入口，承接图片表格相关搜索与场景。

## 测试策略

### 单元测试

覆盖下面几个点：

1. schema 能接受文本块与表格块
2. formatter 能把表格块转成 TXT / MD / HTML
3. PDF block 映射能保留表格块边界
4. 双栏排序和图文归组不会打乱基础阅读顺序

### 组件测试

覆盖下面几个点：

1. 工作区会展示表格能力文案
2. 表格结果会在预览中显示摘要
3. 新入口页与首页能露出表格场景

### 真实样本回归

继续保留之前的 PDF 回归，同时把已经完成的表格 JSON 实验作为能力凭证。后续再把真实用户样本逐步纳入回归。

## 风险与回退

### 风险 1：模型把多列正文误判成表格

缓解方式：

- prompt 里强调“只有存在明确行列关系时才输出 table”
- 低置信度时退回普通段落块

### 风险 2：Markdown 表格对复杂 rowspan 支撑弱

缓解方式：

- HTML 输出保留完整结构
- Markdown 以“简化表格 + records 补充”方式导出

### 风险 3：PDF 中表格块被拆散后顺序错乱

缓解方式：

- 页面排序阶段把表格视作原子块
- 导出阶段再在块内部展开

## 验收标准

满足下面条件即可认为本次落地达标：

1. `Texto formatado` 能接受并渲染表格块。
2. 表格图片在 HTML 预览中显示为结构化表格。
3. PDF OCR 能保留表格块，不把整张表打散成一堆段落。
4. 双栏和多块区域的阅读顺序比当前版本更稳。
5. 首页、主工具页、新入口页都能明确传达 AI 扫描对表格和复杂版面的优势。
